# mamababybites.com

The product website: a plain static site (HTML, one CSS file, images), no build step and no
tracking. It matches the app's look and reuses the app's own text for the legal pages.

```
website/
  index.html        home page (written by hand; its footer is generated)
  learn/            an Articles page and one page per article        ┐
                    (from src/content/solids-articles.json)          │
  support.html      support, common questions, emergency numbers   ┐
  privacy.html      Privacy Policy (from src/content/copy/legal.json)│ generated by
  terms.html        Terms of Use (from src/content/copy/legal.json)  │ npm run website:build
  credits.html      photo credits (from src/content/photo-credits.json)
  404.html          not found page                                   │
  sitemap.xml       every public page, for search engines            │
  robots.txt        lets all crawlers in, points to the sitemap      ┘
  assets/css/site.css
  assets/fonts/     Fredoka (headings) and Inter (text), with their licenses
  assets/img/       logo, favicon, social preview image
  assets/screens/   app screenshots
  assets/js/search.js   article search (runs in the browser, from assets/search-index.json,
                        which npm run website:build writes)
  assets/learn/     article photos, resized from assets/images/insights (webp, 1200px wide)
  assets/foods/     food photos, resized from assets/images/foods (webp, 480px wide)
```

After changing the Terms, the Privacy Policy, photo credits, emergency numbers or articles in
the app, run `npm run website:build` (Node 22.18 or newer) and deploy again so the site matches.
The footer's article links are chosen in `footerColumns` in `scripts/build-website.js`.
When an article gets a new photo in the app, add a resized webp copy to `assets/learn/` (named
after the article id); pages without one simply skip the photo.

## Preview on your computer

```
cd website
python3 -m http.server 8000
```

Then open http://localhost:8000. (Links start at the site root, so opening the files directly
from your disk won't load the styles.)

## Put it online (free)

Either host works; both serve `/support` for `support.html` automatically, so the addresses
in the app and on the App Store (mamababybites.com/support, /privacy, /terms) work.

**Netlify (simplest):**

1. Sign up at netlify.com, then **Add new site → Import an existing project → GitHub** and
   pick this repository and branch.
2. Set **Base directory** to `website`, leave the build command empty, and set **Publish
   directory** to `website`. Deploy.
3. **Domain management → Add a domain**: `mamababybites.com`. Netlify shows the DNS records
   to add at the company where you bought the domain (or lets you move DNS to Netlify).
   HTTPS is set up automatically.

(Or drag the `website` folder onto app.netlify.com/drop for a one-off upload.)

**Cloudflare Pages:** Workers & Pages → Create → Pages → connect GitHub, choose this
repository, leave the build command empty and set the output directory to `website`; then
add `mamababybites.com` under **Custom domains**.

Each push to the branch then updates the site.

## For App Store Connect

- Support URL: `https://mamababybites.com/support`
- Privacy Policy URL: `https://mamababybites.com/privacy`
- Marketing URL: `https://mamababybites.com`

When the app is live, swap the "Coming soon on the App Store" button in `index.html` for the
official Download on the App Store badge from Apple's marketing site, linked to the app's
App Store page.

## Launch sign-up form

The "Get an email when we launch" form on the home page uses **Netlify Forms** (no code or
server of our own). In Netlify, open the site, then **Forms**, and turn on **form detection**
once; the next deploy picks up the form called `launch`. Sign-ups then appear under Forms →
launch, where you can export them. The Privacy Policy's "Launch emails from our website"
section describes this.
